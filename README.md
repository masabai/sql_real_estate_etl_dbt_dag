# Real Estate Sales ELT Pipeline (Connecticut, 2001–2022)

## Project Summary
End-to-end SQL/dbt ELT pipeline on ~1.1M rows of CT property sales.

**Phase I (ELT):** Python-based ingestion to Raw schema, followed by SQL scripts for profiling and Staging.

**Phase II (dbt):** dbt models for transformations, fact/dimension tables, automated tests, and documentation.

**Phase III (Query Interface):** Natural Language Querying (Text-to-SQL) and SQL Interface
This phase allows users to query the clean star-schema of property data using natural language (plain English)
or SQL, with a built-in "Auto-repair" logic for sql syntax errors.

**Model & Execution:** Uses GPT-120b (via Groq) as the reasoning engine to interpret user intent and generate
PostgreSQL code.

**Metadata-Injected RAG:** Instead of vector similarity search, the system injects
explicit database schema metadata into the prompt. This guarantees correct table and column selection.

**Strict Logic Mode:** The model is locked at Temperature 0 to eliminate "creativity." 
This ensures the SQL generated is consistent, repeatable, and won't hallucinate non-existent data.

**Auto-Repair SQL:** If the database returns a syntax error (e.g., lmit instead of LIMIT), the system 
automatically identifies the error and repairs the code before returning the final result.

**Query Observability (Snowflake-Style):** Every query—whether generated by AI or typed by a human—is logged 
in the ai_query_logs table. This provides a full audit trail of user questions and execution timestamps.

### Pipeline Architecture

1. Python ingests raw CSV files into PostgreSQL (raw schema)

2. SQL scripts perform data profiling and staging

3. dbt transforms staging tables into a star schema

4. Airflow orchestrates the ELT pipeline

5. Streamlit provides a query interface (NL → SQL)

### Dataset: Connecticut Real Estate Sales (2001–2022)
~1.1M transaction records.

### Tech Stack

**Docker:** Containerized environment for Airflow, Postgres, and dbt, ensuring reproducible and isolated pipelines

**Airflow:** ETL orchestration + Slack notifications

**Postgres:** Local data warehouse for raw/staging/analytics

**dbt:** Transformations, testing, documentation, star-schema modeling

**Python:** CSV ingestion and EDA

**Slack:** DAG success/failure alerts

**Streamlit:** Full-stack framework for the AI Reasoning Engine, SQL execution, and results UI.

**openai/gpt-oss-120b:** LLM "Query Engine" used for deterministic Text-to-SQL translation (Temperature=0).

**Groq:** Fast inference engine to ensure near-zero latency for the RAG pipeline.
